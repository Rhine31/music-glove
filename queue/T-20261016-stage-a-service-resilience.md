# T-20261016 Stage A service resilience

- 状态：`review`
- 授权依据：用户要求继续开发。
- 目标：补齐分析服务能力检查、不可用反馈和可重试失败的真实重试语义，并建立 iOS HTTP 契约测试。

## 范围

- `object/ios/`：服务状态模型、健康检查 UI、提交可用性与 HTTP 契约测试。
- `object/service/`：失败任务原 ID 重试和并发安全状态切换。
- `README.md`、`CHANGELOG.md` 与本任务记录。

## 验收方法

1. App 能区分分析与渲染能力，服务不可用时给出文本、图标和重新检查动作。
2. 可重试失败以相同幂等键提交后复用原 `job_id` 并再次运行处理器。
3. 同一幂等键更换输入仍返回冲突，不覆盖原始 Vocal。
4. 没有识别到音符时返回不可重试验证失败，客户端引导选择其他音频并创建新会话。
5. 适配器内部异常不向客户端泄露文件路径或自由文本。
6. iOS 验证健康响应解码及 HTTP 错误映射。

## 自验结果

- Python `pytest`：10 项通过，包含失败后同任务重试、空旋律验证失败和内部错误脱敏。
- iPhone 18 Pro / iOS 27 模拟器 XCTest：9 项通过，包含 HTTP 契约、服务状态、轨道去重和更换音频新会话测试。
- 完整 `gate/check.sh`：通过（Python 10 项、iOS 9 项、Markdown 链接、代码围栏与 Info.plist 检查均通过）。
- iPhone 18 Pro 模拟器连接实际本地服务后，正确显示“旋律分析可用，乐器试听未配置”；断开服务后正确显示“分析服务不可用”和“重新检查”。视觉检查发现并修复底部浮动导航遮挡滚动内容的问题。
- 真实 BLE、授权 SoundFont、正式本地持久化与云同步仍未验证。

以上为执行者自验，尚未构成用户验收。
