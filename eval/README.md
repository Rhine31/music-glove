# Music Glove 评估说明

本目录用于记录体验效果、模型质量和研究性评价。`eval/` 回答“效果有多好”，而 [`gate/`](../gate/) 回答“硬性检查是否通过”；评价证据不能替代自动化测试。

## 当前评估基线

| 对象 | 已有证据 | 当前限制 |
| --- | --- | --- |
| iOS 工程 | 可在 iPhone 模拟器构建运行；已有领域、状态与 HTTP 契约测试 | 尚未完成正式用户测试与全页面视觉回归 |
| FastAPI 服务 | 覆盖上传限制、幂等、重试、原始资产保存和派生资产下载 | 当前是单进程开发服务，不代表生产部署能力 |
| Basic Pitch | 已使用合成单音验证音符与 MIDI 生成 | 尚未建立多用户、多噪声环境的授权评估集 |
| 乐器试听 | 服务已定义 FluidSynth + SoundFont 渲染路径 | 当前机器未安装 FluidSynth，也未配置授权 SoundFont |
| 音乐手套 | App 具备模拟连接与状态流转 | 尚未完成真实 BLE、双手同步和硬件在环评估 |

## 后续评价维度

### 1. 哼唱转写

- 音高误差、音符召回率与错误音符率。
- 起音、时值和节奏偏差。
- 不同音域、速度、噪声和录音长度下的稳定性。
- 未识别到旋律时能否给出正确、可恢复的反馈。

### 2. 乐器识别

- 钢琴、吉他、鼓等目标类别的准确率与混淆矩阵。
- 双手时间同步、丢包和动作不完整时的置信度表现。
- 低置信度结果是否避免被错误地当作确定结果。

### 3. 端到端创作

- 上传、分析、结果组装和 MIDI 下载成功率。
- 各阶段 P50/P95 时延与失败类型。
- 重试是否复用同一任务，是否保留原始 Vocal。
- 更换乐器时音符保持不变、只改变音色的正确性。

### 4. 体验与无障碍

- 从 Welcome 到创建第一条音乐轨的任务完成率。
- 错误、空状态、离线状态和恢复路径是否容易理解。
- Dynamic Type、VoiceOver、触控尺寸和 Reduce Motion 表现。
- 设计实现与 `truth/design-screens/` 的一致性。

### 5. 音频效果

- 旋律是否与用户哼唱意图一致。
- 乐器音色是否符合手势识别结果。
- 试听中是否出现明显爆音、截断、节奏漂移或异常音量。

## 评价数据规则

- 优先使用合成数据或已获得明确授权的音频与动作样本。
- 不在报告中写入原始用户音频、可识别动作数据或个人身份。
- 每次评价记录样本来源、版本、参数、运行环境和保留期限。
- 将模型质量、体验评价与硬性测试结果分别呈现，不把主观评价写成“测试通过”。
