# Music Glove 项目章程

本目录说明 Music Glove 为什么存在、当前做什么、暂时不做什么，以及各阶段如何判断是否取得进展。产品、设计与架构细节仍以 [`truth/`](../truth/) 为唯一事实正本。

## 项目使命

Music Glove 通过双手模拟乐器动作与哼唱记录音乐灵感：手部动作决定目标乐器，哼唱决定旋律与节奏，软件负责分析、转换、编辑、试听、保存与导出。

## 当前产品承诺

- 产品硬件负责记录和收集双手动作数据与哼唱数据。
- iPhone App 负责连接、录制、状态展示、结果编辑、项目组织和导出。
- 分析服务必须通过真实 API 将哼唱转换为可编辑音符和 MIDI。
- 系统结合手势识别出的乐器类型生成相应音色；条件不足时明确显示不可用，不伪造结果。
- 原始 Vocal 与动作数据优先保护，派生结果不得覆盖原始资产。

## 当前范围

| 范围 | 当前状态 |
| --- | --- |
| iPhone SwiftUI 高保真界面与创作流程 | 已建立可运行工程 |
| 哼唱上传、任务查询、音符与 MIDI 返回 | 已建立真实 FastAPI 服务 |
| 开发阶段手套连接与状态流转 | 使用明确标识的模拟适配器 |
| FluidSynth + 授权 SoundFont 乐器试听 | 管线已预留，当前环境尚未完成端到端验证 |
| 真实 BLE 协议、双手同步与硬件在环 | 等待硬件规格和样机 |
| 生产云部署、账户、同步和社区 | 尚未进入正式交付范围 |

## 阶段路线

1. **阶段 A：工程闭环**——建立 iOS、API、领域模型、测试和基础 MIDI 流程。
2. **阶段 B：真实设备**——接入 BLE 协议、双手同步、流式落盘和离线恢复。
3. **阶段 C：分析与编辑**——完善云端精修、多轨编辑、混音和自动保存。
4. **阶段 D：项目与交付**——完成账户、同步、完整导出、隐私与发布门禁。
5. **阶段 E：社区能力**——在范围、审核与可见性规则确认后再实施。

## 成功标准

- 用户能够从动作与哼唱进入可继续编辑的音乐项目。
- 重试、断网和失败不会重复任务或丢失原始数据。
- 未实现或不可用的能力被准确说明，不以模拟结果冒充真实能力。
- 核心流程满足测试、无障碍、隐私和性能要求。
- `truth/`、`object/`、测试和用户可见说明保持一致。
